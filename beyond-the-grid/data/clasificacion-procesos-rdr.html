Leyenda de categorías

📤 Extracciones (fichero) — RDR genera un fichero y lo envía/deposita para un sistema consumidor
📋 Cargadores Excel/CSV — El usuario prepara una plantilla Excel/CSV y la deposita para que RDR la procese
📥 Cargas de servicios externos — Un sistema externo deposita fichero automáticamente que RDR recoge y carga
🔄 Conciliaciones — Comparación de datos RDR con los de otro sistema para detectar y resolver diferencias
🔧 Gestión y operación — Mantenimiento, auditorías, monitorización, procesos auxiliares
↩️ Handler ESB (petición/respuesta) — Escucha en cola KYRS.RDR.*.REQUEST → ejecuta query → responde en *.RESPONSE
➕ Alta/Setup de entidades (API) — Recibe petición de alta/modificación vía ESB y ejecuta la operación sobre DDFF
📨 Recepción mensajes externos (MQ) — Listener en cola MQ de sistema externo — recibe respuestas o notificaciones

Metodología de clasificación

Fuentes:

  • Wiki RDR — sección "Componentes y cesiones" → tabla "Procesos batch de carga"
  • assembly_file.xml — MessageListeners reales (colas JMS)
  • Inventario consolidado de procesos (procesos-rdr-explorer.html)

Regla de clasificación batch (según wiki):

  • Si la wiki lo llama "Conciliación..." → va a Conciliaciones
  • Si la wiki lo llama "Carga..." → va a Cargas de servicios externos
  • Si usa plantilla Excel (Plantillas de carga en wiki) → va a Cargadores Excel/CSV
  • Si genera fichero para consumidor (Cesiones vía fichero en wiki) → va a Extracciones

Criterios BATCH:

  • Extracción: RDR ejecuta query SQL → genera fichero → deposita en ruta del consumidor
  • Cargador Excel/CSV: Usuario prepara plantilla Excel → genera CSV → deposita en carpeta → FileWatcher lo recoge
  • Carga de servicio externo: Sistema externo deposita fichero automáticamente → RDR lo recoge y carga
  • Conciliación: Compara datos RDR con fichero entrante de otro sistema → genera diferencias/alertas/actualizaciones
  • Gestión y operación: Mantenimiento, auditorías, monitorización, bajas, predicciones

Criterios ONLINE (basado en listeners):

  • Handler ESB: Listener en KYRS.RDR.*.REQUEST → ejecuta query → responde en *.RESPONSE. La publicación (PUBLISH/INITIALLOAD) es una acción del handler, no un proceso separado.
  • Alta/Setup online: Listener en colas de modificación (PARTYSETUP, SISETUP, MODSDI) → alta/actualización de datos maestros
  • Recepción MQ: Listener en colas IBM MQ/TIBCO de sistemas externos → recibe mensajes asíncronos (respuestas, notificaciones)
